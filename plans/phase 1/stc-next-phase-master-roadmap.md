## Approach — Phase 6 workstreams

Order = dependency order; the tree builds and existing 51 tests stay green after each WS. WS1 blocks WS2/WS3/WS7; WS4/WS5/WS6 are independent of each other and can land in any order after WS1; WS8 last (it consumes gate evidence from WS6 and receipts from the existing merge queue).

### WS1 — Auth & credential substrate (BLOCKING; extends the SecretBroker stub, no new parallel system)
1. New `studio-core/src/auth/mod.rs`: `pub enum AuthKind { ApiKey, OAuth, Local, CliDelegated, CloudIam }`; `pub struct CredentialStore` backed by the OS keyring (`keyring` crate: macOS Keychain / Linux Secret Service) with an encrypted-file fallback `credentials.vault` (0600, master key from keyring) for headless lanes. Every stored item: `{label, auth_kind, material, quota_window, expires_at}`.
2. Upgrade `SecretBroker` in `roles/mod.rs:44-63` — keep the one-shot `mint(scope) -> token` / `redeem(token, scope)` contract and its tests; add `pub fn checkout(&mut self, token: &str, lane: &str) -> Result<PathBuf, String>` that materializes a **short-TTL token file** at `profile_dir(base, lane)/auth/` (0600) and registers expiry in the store. Invariant (existing, keep): workers/agents never see raw credentials — capability handles only.
3. `auth_kind: AuthKind` becomes a field on provider connections (WS2). `CliDelegated` = harness owns the OAuth dance (Claude Pro/Max, ChatGPT Plus/Codex, Copilot); STC only meters. Reason (ToS): Anthropic prohibits third-party harness use of Claude Pro/Max — verified via opencode.ai/docs/providers; never reimplement a harness OAuth client.
4. Metering: extend `state/mod.rs` `record_tokens`/`token_ledger` rows with `billed_kind` (allowed to flip subscription→per-token overage) and quota-window events; budget arms on `input+output+cache_write`, `cache_read` excluded (already the roadmap rule; make the schema match).

### WS2 — Model management: in-core provider hub + role slots (D-MODEL)
1. New `studio-core/src/provider/mod.rs`: `Connection { name, auth_kind, base_url, models: Vec<ModelId>, cost: CostTable }`, `RoleSlot { role, ordered_connections: Vec<ConnectionId>, tier: TierPreset }`. Three shipped onboarding profiles as editable rows: `Max-first`, `API-cheap`, `Local-only`. Roles name slots, never providers. Code-enforced: auto-routing (if ever enabled per-slot) is **forbidden on `coder.primary` and `reviewer`** (review independence); sticky-per-task affinity — one task pins one connection at dispatch; fallback on hard failure/quota exhaustion only, never mid-task for cost.
2. Minimal internal LLM client (`provider/client.rs`) for daemon-owned calls only (Manager scope negotiation, reviewer judgment): `anthropic-messages` + `openai-completions` dialects, retry + circuit breaker + cost accrual into `token_ledger`. `openai-responses` deferred until a caller needs it. Harness-internal calls stay harness-native.
3. Harness config generation (kills hand-edited JSON): `provider/sync.rs` emits `.opencode/opencode.json` and pi `models.json`/`auth.json` into per-lane profile dirs from the same connections; secret values written as bind-time placeholders resolved by `SecretBroker::checkout`, never persisted in locks or committed files (kasetto pattern).
4. Upstream gateways = provider profile `Upstream { url, master_key }` (OmniRoute/LiteLLM/Bifrost/OpenRouter all pass through the same way). No sidecar ships. (OmniRoute is already running in this workspace — first integration target.)
5. Cockpit Providers view (`cockpit/src/pages/Providers.tsx`): 4-state connect — pick source → connect with **live ping proof** (never "Connected" from a saved string) → assign roles showing *which account gets billed* → live status with 24h staleness badge. Import of existing harness configs is read-only; export to harness is explicit with diff preview.

### WS3 — Harness manager + real session execution (closes gap A3)
1. New `studio-core/src/harness/mod.rs`: `probe()` (`which claude codex opencode pi` + known config dirs) → `HarnessSource::Host | Managed { name, version, dir }`; `ensure_installed()` downloads **container-native official releases** into `~/.studio/harness/bin/<name>/<version>/`. Never prebake into images (A4), never mount host binaries into containers (ABI/shebang hazard — antigravity is right about that half). Version dir, not image layer, absorbs CLI update cadence.
2. Extend `session/cli_shim.rs` `LocalCliCapabilities::for_cli` with `opencode` and `pi` profiles (today only `claude`/`codex` exist; everything else falls to `Resume::None`).
3. Real harness spawning: session bridge executes the harness CLI via the existing `mcp/process.rs` `ProcessSpec` chokepoint (`shell:false`, bounded output, timeout), bound to `task_id` + role manifest, with per-lane config env (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `OPENCODE_CONFIG_DIR`, `GEMINI_FORCE_FILE_STORAGE=true` for Antigravity) all pointing under `profile_dir(base, lane)`.
4. Legacy lanes: OAuth subscription CLIs (Claude Code, Codex) run as `cli_delegated` lanes on the host control plane (their OAuth needs the host keychain — this is why the control plane is native, see D-TOPO). Mounted-config escape hatch stays: a user's existing `~/.claude` etc. is detected as `Host` source and reused with zero reconfiguration.

### WS4 — Persistence, migrations, packaging (D-TOPO)
1. Versioned migrations: `StateStore::migrate` and `MemoryStore::migrate` become forward-only `PRAGMA user_version` steps (keep idempotence); before each migration `VACUUM INTO studio.db.bak.<ts>`; engine refuses to boot against unknown `/state/.layout-version` stamp.
2. State layout — one named volume per class, never a mega-volume: `studio-state` (db+WAL), `studio-evidence` (sha256 blobs), `studio-logs` (JSONL, rotated), `studio-harness` (per-lane configs/auth, per-lane subdir), `studio-toolchains` (node/python/uv/rustup caches, read-only into workers). Repos and `.worktrees/` are **host-identical bind mounts**; the engine owns all `git worktree add/lock/prune` (existing `WorktreeManager`).
3. `studio backup` (db + evidence) and `studio export` (db + evidence + config **without** secrets; `--include-secrets` writes an age-encrypted envelope) in `adapters/cli`.
4. Sandbox worker tier per D-TOPO: rootless podman/docker per-task worker executing agent-written code only; workers receive short-TTL `SecretBroker` tokens and **never** `docker.sock`, `~/.ssh`, `~/.aws`, `~/.gnupg`, or the keychain. Engine/scheduler never containerized.

### WS5 — Memory: ledger projection upgrades (D-MEM)
1. Write-path code-derivability deny-list in `memory/store.rs` `put`: refuse anything derivable from the repo, git history, the ledger, or receipts (Claude Code's rule; highest-leverage memory change).
2. `memory/lifecycle.rs` rows gain `valid_from_seq`, `valid_to_seq`, `supersedes_id` referencing plan-ledger hashes (`ledger/mod.rs` `LedgerEvent.seq`/`plan_hash_after`) — bi-temporal supersession with cryptographic backing; retrieval excludes superseded rows by default (schema change rides the WS4 user_version migration).
3. The high-value artifact is a ≤250-token summary anchored to `(path, symbol, commit_sha, plan_hash)`; raw trajectories are never injected. Memory is namespaced per repoId, shared across all worktrees of that repo (parallel lanes must not fragment it).
4. Bound rungs hard (existing reapers): `MEMORY.md` ≤200 lines / 25KB; rung-2 retrieval budget 300–500 tokens; L4 vector stays opt-in with mandatory reranker (existing fail-closed interface — keep).
5. Consolidation = serialized, off-critical-path step (Codex two-phase shape: leased per-session extraction → serialized consolidation → `max_unused_days`/`usage_count` pruning). Never on the write path.
6. Engram eval spike (gated): wire Engram's MCP as an optional retrieval backend behind the L3 interface for one lane; measure cross-session recall + FTS latency (<500ms @ 10k docs). Kill: recall misses or >1 day ops burden → drop, L3 FTS5 (`memory/store.rs`) remains the only backend.

### WS6 — Quality gates & anti-circumvention (D-QUAL)
1. Diagnostic Broker (new `studio-core/src/quality/`): run **CLI diagnostics** (authoritative — LSP is a navigation aid only, never a gate): `cargo clippy -D warnings` + `rustfmt --check` on changed crates; `fallow audit --format json` on TS/JS surfaces (`cockpit/`, `adapters/` TS); `ruff`/`biome` for Python/TS; `gitleaks` for secrets. Normalize to SARIF 2.1.0 — **handle optional `result.level`** (fall back to `rule.defaultConfiguration.level`; naive `select(.level=="error")` passes a repo full of errors). Severity budget: block **NEW** error-level findings only (inherited excluded, matching `fallow audit`'s changed-files gate). Emit `agent_prompt` fix-tasks into `verify` receipts.
2. `prek` (not lefthook, A9) hooks: pre-commit = format + fast lints + gitleaks + `fallow audit` + config-integrity, budget <15s; pre-push = typecheck/tests affected + `cargo-audit`/`osv-scanner` on lockfile change + marker-file freshness (pre-commit writes a tree-hash marker; pre-push rejects stale — this survives `--no-verify` on commit).
3. Anti-circumvention is process-level (prompt rules are proven useless — claude-code#40117: 6 bypassed commits): command guards in the session bridge deny `--no-verify`/`-n`, `core.hooksPath` overrides, `HUSKY=0`/`LEFTHOOK=0`/`SKIP=*`, `git stash`+commit combos, and writes to gate configs (`biome.json`, `tsconfig.json`, `clippy.toml`, `Cargo.toml [lints]`, prek config, `.claude/settings.json`); RoleManifests deny MCP write-through tools (`push_files`/`create_or_update_file`/`merge_pull_request` class) that skip local hooks; every Bash command logged (git does not record `--no-verify`; our ledger must).
4. Suppressions never live in source (`#[allow]`, `eslint-disable`, `# type: ignore` are gate failures unless routed): SARIF suppression objects with required justification, owned by CODEOWNERS; CI runs with ignores disabled. Config-integrity: gate-config diffs require CODEOWNERS approval; agents cannot self-approve.
5. Extend `verify/dod.rs` receipts to carry gate evidence: `tests_green`, `syntax_ok`, `diagnostics_budget_ok`, `suppression_approved` — the merge queue (existing `merge/mod.rs` `gated_merge`) consumes these, unchanged turnstile semantics.

### WS7 — RolePack v2 + one flagship pack (D-SUBSTRATE)
1. Extend `RolePack` (`roles/mod.rs:10-17`) — add fields `system_prompt: String`, `mcp_manifest: RoleManifest` (reuse `mcp/registry.rs` types), `model_slot: String`, `harness_profile: HarnessProfile`, `spawns: SpawnPolicy`, `output_schema: Option<serde_json::Value>`; add serde `load`/`save` (today the struct is constructed only in its own test). `SpawnPolicy` is non-escalating: a child requesting authority above its parent is **rejected with a typed error, never downgraded** (happier pattern).
2. `rolepack.yaml` + `rolepack.lock`: content hashes over 4 asset kinds (skills, commands, MCPs, instructions), extending the shipped `skills-lock.json` pattern; `--locked` in CI and worktree provisioning; managed-block upsert into `CLAUDE.md`/`AGENTS.md` (never full-file rewrite); secrets as bind-time placeholders only. `RolePack::check_parity` already catches phantom tools — extend it to all emitted targets.
3. Authoring contract per D-SUBSTRATE; emission targets compiled from one source. Registration-parity tests run against every emitted target (they already caught the phantom-tool class).
4. Ship **one** flagship RolePack (`coder-web`: skills + MCP slice + model slot + Diagnostic Broker quality spine) end-to-end. A catalog is content and races to the bottom (gsd-core ships 33 agents, wshobson/agents ~40k★); expansion beyond the flagship is gated on hypothesis H-C (compiled targets within 5% of native role-fidelity across 6 roles).

### WS8 — Contract runtime (the moat; last, consumes WS6 evidence)
1. Frozen-candidate evidence gate (gentle-ai pattern, extended to delivery — they explicitly refused delivery gating, which is where our merge queue lives): `verify/freeze.rs` — freeze the candidate diff → risk tier → bounded lens depth → **one** bounded correction round → acknowledgement receipt that **burns**; `merge/mod.rs` `gated_merge` requires the burned receipt to land. Hypothesis H-B: ≥50% fewer review→fix→re-review loops on 20 tasks (kill: <25% or defect-catch drop).
2. Action registry + surface exposure matrix (happier pattern): every daemon action typed `{ action_id, surfaces: Vec<Surface>, exposure: Direct | Discoverable, policy: Allow | Ask | Deny }`; cockpit exposes the matrix; the scheduler enforces it.
3. Deterministic next-transition owned by the scheduler state machine (gentle-ai pattern) — extend the existing zero-model scheduler, no model in the transition loop.

## Assumptions & contingencies

GPU work always runs on host (Metal cannot enter a Docker VM).
- **D-MODEL (model management) — CONFIRMED: in-core provider hub + 2-dialect internal client + gateway passthrough profiles.** Fallback if a gateway integration is demanded early: OmniRoute profile first (it is live in this workspace), LiteLLM/Bifrost identical passthrough later; never make a gateway a required component.

- Report statistics (A10) are approximations: any count that reaches code comments or docs is re-fetched at write time or marked `unverified`.
- Scope boundary (inline): no marketplace, cloud hosting, mobile companion, or voice; no OAuth client reimplementation; no LSP-as-gate; no shipped gateway sidecar.
