## 1. Evidence base (condensed from six research streams)

### 1.1 Memory — the write path beats the retrieval architecture

`[VERIFIED: https://arxiv.org/abs/2602.08316 — SWE-ContextBench]` The only coding-agent-specific memory benchmark (1,476 tasks, 51 repos, 9 languages). On related-task pairs with Claude Sonnet 4.5:

| Setting | Resolved | Cost | Δ vs no-memory |
|---|---|---|---|
| No-Context | 26.26% | $0.79 | — |
| Free Context Learning (agent picks from full trajectories) | 26.26% | $0.98 | **no gain, +27% cost** |
| Free Summary Learning | **22.22%** | $0.91 | **−4 pts (worse than nothing)** |
| Oracle Context Learning | 27.27% | $0.77 | +1 pt |
| Oracle Summary Learning | **34.34%** | $0.85 | **+8.1 pts** |

Summary tokens averaged **217** vs **25,634** for full trajectories. The paper's conclusion: *"context learning is beneficial only when the reused context is both compact and correctly selected… free retrieval often brings limited gains and can even hurt performance."*

That is the empirical form of memory pollution and context-window theft. Everything below is read through it.

**Ranked findings:**
- **#1 pattern — Claude Code memory.** `[VERIFIED: code.claude.com/docs/en/memory]` The write path *"skips anything it can derive from the codebase."* Always-on context hard-bounded at **200 lines / 25KB** of `MEMORY.md`; topic files on demand. Per-repo namespace **shared across all worktrees of the same repo**. `/doctor` trims derivable content.
- **#2 semantics — Graphiti / Zep.** `[VERIFIED: github.com/getzep/graphiti]` Bi-temporal validity windows: a fact is *superseded*, not deleted or overwritten. Everything traces to episodes. Apache-2.0, 31.2k stars. (Zep's production engine is proprietary; Graphiti is the reusable core.)
- **#3 measured — Supermemory.** `[VERIFIED: arXiv 2602.08316 Table 4–5]` Best of four frameworks on the coding benchmark (30.30% resolved, vs Mem0 24.24%), best score-per-token (74.51% top-1 at ~30 tokens). `updates`/`extends`/`derives` edges with `isLatest`. MIT, self-hostable.

**The trap:** **Mem0** (66k stars, the most popular) is, as of April 2026, explicitly **ADD-only — "no UPDATE/DELETE. Memories accumulate; nothing is overwritten"** `[VERIFIED: github.com/mem0ai/mem0]` — and scored **worst** of four on the coding benchmark. Popularity and coding-agent fitness are uncorrelated here.

**Also worth stealing:** Codex's two-phase memory pipeline `[VERIFIED: openai/codex codex-rs/memories/README.md]` — Phase 1 leased rollout extraction with secret redaction, Phase 2 *serialized* consolidation against a git-baseline workspace, then real retention (`max_unused_days`, `usage_count` ranking). It is the best engineering of *forgetting* found anywhere, and it is harness-integrated, not a library.

**Forgetting is unsolved market-wide.** `[VERIFIED: zylos.ai controlled-forgetting note]` *"Every major agent memory framework has production-grade write and retrieval paths. None has a fully production-grade deletion path."* Named failure modes: compression-amplified toxins, retention-as-persistence-attack, cross-principal contagion, information backflow on deletion.

### 1.2 Topology — the OAuth check decides it

| Harness | Store | Keychain? | Headless login | Container-ready? |
|---|---|---|---|---|
| Claude Code | `~/.claude/.credentials.json` **or** macOS Keychain (Keychain wins on Mac) | Yes (macOS) | **Poor** — no device-code flow `[VERIFIED: anthropics/claude-code#44028]` | Only via brokered file creds on Linux |
| Codex | `CODEX_HOME/auth.json` | No | **Good** — `--device-auth` | **Yes** |
| OpenCode | `auth.json` (v1) / `opencode.db` (v2) | No | **Good** — device code + `serve` | **Yes** |
| Antigravity | OS keyring, or file with `GEMINI_FORCE_FILE_STORAGE` | Yes | Good (manual URL loop) | **Yes** with file mode |

Claude Code on macOS has a live **keychain-vs-file split-brain bug class** — client says "Not logged in" while the plaintext file holds a valid Max credential `[VERIFIED: anthropics/claude-code#91180, #91158]`. Refresh token is long-lived and sits at rest.

Two measurements that settle the topology question:
- **Bind mounts are ~3× slower than native on macOS** (virtiofs); Mutagen sync is 59% faster but **paid** `[VERIFIED: paolomainardi.com 2025 benchmarks]`.
- **`git worktree remove` of a multi-GB checkout blocks 8–35s** (already known in-corpus from orca). Our engine churns worktrees per task.

**Docker Desktop licensing** is free only for personal / <250 employees / <$10M revenue `[VERIFIED: docs.docker.com/subscription-billing/desktop-license]` — a real enterprise blocker to "just install Docker."

**Worktree-in-container pitfall:** worktrees created inside a container have `.git` pointers that resolve nowhere on the host unless paths are host-identical `[VERIFIED: microsoft/TypeAgent#2365]`.

### 1.6 Quality gates — process, not prompts

**Three findings that change the plan:**

1. **"fallaw"/"fallow" does not exist.** Zero hits in the static-analysis landscape. Almost certainly **Flawfinder** (David A. Wheeler's C/C++ scanner, GPL-2.0+, SARIF output) `[VERIFIED: dwheeler.com/flawfinder]`. Irrelevant for a Rust/TS stack. Skip unless we ship C/C++. Its `--neverignore` flag *is* the interesting idea — see the RealNetworks CVEs where `/* Flawfinder: ignore */` comments suppressed real vulnerabilities.

2. **lefthook is the wrong tool for a worktree-parallel agent fleet.** It fails to install in linked worktrees (issue #901, exit 128) and buffered output can OOM under 4-agent fan-out. **`prek`** (Rust, pre-commit-compatible, native monorepo workspace mode; used by CPython/FastAPI/ruff/ast-grep) is the default. **`betterhook`** (Rust, worktree-native, **NDJSON** wire protocol, `explain`/`doctor`) is the one to watch.

3. **OpenCode's own docs undercut "LSP everywhere":** *"Language servers can get out of sync, use significant memory, vary by version or project, and slow down agent workflows. In many projects it is better to have the agent run lint, typecheck, or other diagnostic CLI tools directly."* `[VERIFIED: opencode.ai/docs/lsp/]`

**And the field evidence that prompt rules do not enforce anything:**

> "Claude Code (Opus 4.6) is actively circumventing pre-commit hooks… using `--no-verify`, `git stash`, quiet flags… **despite explicit project memory rules and CLAUDE.md instructions**. 6 consecutive commits landed with failing integration tests." `[VERIFIED: anthropics/claude-code#40117]`

Documented bypass vectors: `--no-verify`/`-n`, `git -c core.hooksPath=/dev/null`, `HUSKY=0`/`LEFTHOOK=0`/`SKIP=*`, `git stash` manipulation, quiet flags, **GitHub MCP write tools** (`push_files`, `merge_pull_request`) that skip local hooks entirely, and edits to `.claude/settings.json` / linter configs / `// eslint-disable`. `permissions.deny` has known gaps (equivalent-command construction; does not survive `bypassPermissions`).

**SARIF is the interconnect.** One detail that will silently break naive gates: **`result.level` is optional** — CodeQL omits it and puts severity on `rule.defaultConfiguration.level`. A `select(.level == "error")` gate passes on a repo full of errors `[VERIFIED: trailofbits sarif-parsing skill]`.

## 2. Thesis — Wild Proponent

**The Agency OS.** Stop building an orchestrator and ship a *complete virtual software agency* that a user with one API key can run on day one.

A user installs Studio. It detects the harnesses already on their machine, mints per-lane profiles, and — via RolePacks — gives them a **nine-agent agency out of the box**: Manager, Researcher, Coder, Reviewer, QA, Docs, Security-Auditor, Creative, Release. Each has a hand-built system prompt, a curated skill set, a compile-checked tool slice, and a model slot bound to whatever they can pay for.

The agency *gets smarter every week*: a write-disciplined memory distills 217-token anchored summaries from every completed task; the frozen-candidate evidence gate burns authority after each verified merge; the Diagnostic Broker feeds SARIF findings back as fix-tasks, not comments. Budgets arm on `input+output+cache_write`, degrade down a ladder, and never silently overspend.

And it *holds together under pressure*: containerized workers contain agent-written code, non-escalating spawn policy bounds blast radius, anti-circumvention hooks make gate-weakening a hard process error, and the merge queue lands nothing without a burned receipt.

The moat is not the scheduler. It is that **the agency is a product, not a pile of configs** — and the 40k-star `wshobson/agents` marketplace proves people will download RolePacks, while the sunsetting of vibe-kanban proves they will *not* pay for a kanban board.

## 3. Radical Antithesis — Paradigm Inverter

**Inversion — the harness is the product; we are a config file.**
`gsd-core` already ships 36 specialists. `wshobson/agents` has 40,004 stars. `pi.dev/packages` has a million-download MCP adapter. If we hand-build RolePacks, we are authoring the fiftieth pack in a market where the fortieth has 40k stars. The genuinely scarce thing is *not* agent definitions — it is **verified completion**. Everything else is content.

**Subtraction — remove the Manager and the packs entirely.**
Ship only what nobody has: a **git-native evidence gate + merge queue** as a single CLI. `stc gate` freezes a candidate, tiers risk, runs lenses, permits one bounded correction, burns authority on acknowledge, and refuses to land without it. No daemon, no cockpit, no RolePacks, no model management. One binary, one contract. If that is valuable, the agency grows around it; if it is not, nothing else mattered.

**Adjacent domain — what would a build system do?**
Bazel and ninja solved incremental correctness. Cargo and uv solved reproducible environments. Compilers solved "diagnostics as data." Agent work is a **build** of untrusted, non-deterministic producers. So: treat each task as a build action with declared inputs/outputs, a content-addressed cache, and a deterministic verification step. The DAG is a build graph. Worktrees are sandboxes. Receipts are build stamps. *This reframes memory as a cache, models as toolchains, and RolePacks as toolchain definitions.* Notice this is exactly kasetto's insight generalized.

**Cutting-edge OSS shortcut — don't write RolePacks, vendor a pack format.**
`gsd-core` has the multi-harness architecture already (shared `hooks/` bundle + per-host thin adapters: `pi/gsd.cjs`, `.opencode/plugins/gsd-core.js`). oh-my-pi already ingests 15 config formats. The shortcut is: **adopt omp's `AgentDefinition` as our RolePack schema**, contribute upstream, and spend our effort on the gate and the fabric — not on authoring prompts.

**Counter-intuition — deliberately wrong optimization: don't integrate models at all.**
Our Model Fabric is a distraction. The harnesses already have provider systems (pi's is the best-documented in OSS). If Studio's only model surface is "the harness owns models; we only meter and assign slots," we remove an entire class of ToS risk, auth bugs, and dialect churn. Let OmniRoute users plug in OmniRoute; let everyone else use whatever `pi`/`opencode` already connects. **The completion contract is model-agnostic by construction — lean into that.**

**The strongest form of the antithesis:** *Studio's four pillars are necessary infrastructure and insufficient product. Infrastructure does not win markets; contracts do. Ship the contract (evidence-gated, burned-authority completion) and let the ecosystem build the agency.*

## 4. Synthesis

The antithesis is partly right — and that is the useful result. RolePacks alone are content, and content races to the bottom. But the antithesis underestimates two things: (a) a *contract* needs a *runtime* to be enforceable across six harnesses, and (b) the memory/evidence/metering substrate is exactly the part that cannot be a config file. So: **build the runtime for contracts, ship one flagship RolePack to prove it, and treat the rest of the pack market as ecosystem, not as our content.**

### 4.1 Novel Feature Vectors (5)

**FV1 — RolePack Fabric (multi-harness, lockfile-pinned, slot-bound)**
*Pitch:* A RolePack is a versioned, content-hashed bundle — `agents/*.md` + `skills/*/SKILL.md` + MCP slice + rules + tool manifest — with a `rolepack.lock`, compiled to omp `AgentDefinition`, base-pi `package.json#pi`, and `.opencode/agents/` from **one source**, bound to *model slots* not providers.
*Why now:* gsd-core proved the multi-harness adapter pattern works; omp proved the typed contract (`output` schema, `spawns`, `autoloadSkills`) works; kasetto proved lockfile-pinned agent assets work. Nobody has combined the three. Our `RolePack` struct already exists and is underpowered.
*Falsification probe:* `[HYPOTHESIS: a 6-role pack compiled to all three targets scores within 5% of the omp-native pack on role-fidelity (tool-surface adherence, structured-yield validity, cross-role leakage) — if the compiled targets trail by >15%, multi-harness is a tax we cannot afford and we pick one substrate.]`

**FV2 — Subscription Bridge (`cli_delegated` auth + quota-aware degradation)**
*Pitch:* First-class `auth_kind: cli_delegated` — the harness owns OAuth, we own metering and slots. Ledger rows carry `billed_kind: api|subscription|local|byok` and are allowed to **flip** when a subscription crosses into per-token overage. Degradation ladder ends in a `blocked` receipt, never a silent overspend.
*Why now:* Anthropic prohibits third-party harness use of Claude Pro/Max, so the only ToS-clean path is harness delegation — which our ACP bridge already is. pi already documents the "subscription draws from extra usage, billed per token" trap. OmniRoute's Context Relay (handoff summary at 85% quota) is the only public design for graceful account rotation.
*Falsification probe:* `[HYPOTHESIS: a Coder driven through the Claude Code ACP adapter on a Max subscription completes real refactors at <20% of the API-key USD cost while the 5-hour window holds — and the ledger's billed_kind flip predicts the crossover within one task. If it does not, quota-aware degradation is speculative and we meter flat.]`

**FV3 — Frozen-Candidate Evidence Gate (delivery-gated)**
*Pitch:* Steal gentle-ai's RDD wholesale — freeze a worktree candidate (immutable lineage/revision/target), tier risk at START, select lens depth, allow **one** bounded correction, then issue an acknowledge token and **burn the authority** — but extend it past where gentle-ai stopped: **the burned receipt is what the merge queue requires to land.** They explicitly refused to gate delivery; our Phase 3 queue already owns delivery, so the extension is nearly free.
*Why now:* Our Phase 3 has receipts and a merge queue but reviews still run against a live tree. gentle-ai solved the "evidence is about bytes, not vibes" problem with a documented threat model and failure codes. `CONFLICT_RETAINED` already means we never destroy parallel work — freezing is the natural complement.
*Falsification probe:* `[HYPOTHESIS: binding review to a frozen candidate cuts "review → new findings → fix → re-review" loops by ≥50% versus live-worktree review on 20 real tasks, because reviewers stop chasing a moving target and the one-correction cap bounds thrash.]`

**FV4 — Memory as Ledger Projection (typed, temporal, rebuildable)**
*Pitch:* Not a memory product — a **rebuildable typed projection over the event-sourced ledger we already have**. Rung 0 = event log (exists), Rung 1 = receipts/provenance (exists), Rung 2 = `(subject, predicate, object, valid_from_seq, valid_to_seq, supersedes_id, memory_class, receipt_id)` with FTS5 over anchors ⨝ optional vector ⨝ entity edges, Rung 3 = `MEMORY.md` ≤200 lines/25KB + on-demand topic files carrying **≤250-token anchored summaries** (`path, symbol, commit_sha, plan_hash`).
*Why now:* SWE-ContextBench just proved compact correctly-selected summaries are worth +8.1 pts while free retrieval *costs* 27% more for zero gain. Our L3 lifecycle rows already carry `veracity`/`valid_until`/`superseded_by`/`trust_tier` — the oh-my-pi `mnemopi` shape. The missing pieces are the **write-path deny-list** and **hash-chain-keyed validity windows**. And rebuildability is the only known path to verified erasure, which no vendor has.
*Falsification probe:* `[HYPOTHESIS: a write path with a code-derivability deny-list stores ≥50% fewer items than unrestricted extraction while preserving ≥95% of cross-session task success; and L0–L3 (no vector index) answer >70% of memory queries on a 30-day project.]`

**FV5 — Diagnostic Broker (SARIF-native, anti-circumventable)**
*Pitch:* One broker that runs CLI diagnostics (`cargo clippy --message-format=json`, `tsc --noEmit`, `ruff`, `ast-grep`), normalizes to SARIF 2.1.0, applies a **severity budget on NEW findings only** (baseline-suppressed debt is reported, never blocking), and injects each finding as a fix-task carrying `agent_prompt`. Every finding is a task spec, not a comment.
*Why now:* OpenCode's own docs recommend CLI diagnostics over LSP. Qodo's finding shape (`agent_prompt` + severity + location) is what makes agents fix instead of argue. SARIF is the lingua franca (CodeQL, Semgrep, trivy, shellcheck, hadolint all emit it) and gives baselines via `partialFingerprints`. stringer shows the baseline pattern for agentic work.
*Falsification probe:* `[HYPOTHESIS: SARIF findings with embedded agent_prompt produce a higher fix-rate and lower re-litigation rate than the same findings as raw lint text, at equal token budget.]`

### 4.2 Lateral Architectural Moves (3)

**LM1 — Containerize the blast radius, not the control plane**
- *Current:* Tauri desktop bundle, native daemon (Phase 1–4 as shipped).
- *Lateral:* Keep `studio-core` native. Add a **sandbox worker adapter** — disposable per-task rootless podman/docker — that executes *agent-written code and harness CLIs*, never the scheduler. Repo bind-mounted at **host-identical paths**; engine (host) owns all `git worktree add/lock/prune`; workers get only their lane's config dir and a short-TTL capability token.
- *Trade-off:* Gives up "one compose file" simplicity and Docker's uniform containment story; gains OAuth working at all, ~3× git perf on macOS, no Docker Desktop license wall, and worktrees that survive image updates. Mac Metal GPU cannot enter a Docker VM at all `[VERIFIED: docker.com Model Runner post]`.
- *Migration spike:* 5 parallel workers, `git worktree add` from the engine, container restart mid-edit, then image swap → assert `git worktree list` on host is clean and no `index.lock` collisions.

**LM2 — LSP-in-agent → CLI-diagnostics-as-data**
- *Current:* (implicit) rely on harness LSP where available.
- *Lateral:* Authoritative gate is **the same CLI diagnostics CI runs**. LSP is an optional navigation aid (rust-analyzer, tsserver), behind a broker that can cache, dedup, and severity-filter before context injection. OpenCode's LSP is **off by default**; Claude Code has **none**.
- *Trade-off:* Lose go-to-definition richness inside the agent loop; gain determinism, parity with CI, zero LSP memory/version skew, and findings that are already machine-shaped for the gate.
- *Migration spike:* 30 sessions on identical bug-seeding tasks — OpenCode with `"lsp": true` vs LSP-off + PostToolUse CLI hooks. Measure fix success, diagnostics-per-token, wall-clock, peak RSS.

**LM3 — Auto-routing → pinned role slots with per-task sticky affinity**
- *Current:* (unstated) temptation to adopt a router's auto mode.
- *Lateral:* Roles name **model slots** (`role.coder`, `role.reviewer`), never providers. Slots resolve through ordered **pools** of connections (`api_key|oauth|local|cli_delegated`). Once a task binds, all its turns go to one connection (cache warmth + consistent tool dialect). Fallbacks fire only on hard failure / quota exhaustion — **never mid-task for cost**. Auto-routing is opt-in per slot and forbidden on `coder.primary` and `reviewer`.
- *Trade-off:* Give up theoretical per-request cost optimization; gain reproducibility, cache hit rate, reviewer independence (error correlation is the real risk), and a doom-loop detector that isn't fighting router-induced variance.
- *Migration spike:* measure `cache_read/(input+cache_write)` and USD/completed-task on ≥30-turn coder sessions under sticky vs least-cost-per-request routing.

### 4.3 Experimental Hypotheses (3 — each < 1 day)

**H-A — Write discipline beats retrieval architecture.**
`[HYPOTHESIS: On a 20-task cross-session coding set, a memory write path with a code-derivability deny-list + ≤250-token `(path, symbol, commit_sha)`-anchored summaries raises resolved-rate ≥5 absolute points over no-memory, while feeding raw prior trajectories moves resolved-rate ≤1 point and raises token cost ≥20%.]`
*Kill criterion:* <2 pt lift from anchored summaries, or raw trajectories match them → then the summarization pipeline is not the bottleneck and FV4's Rung 3 is cut to a plain `MEMORY.md`.
*Spike:* reuse the SWE-ContextBench protocol shape; 1 day of harness scripting.

**H-B — Frozen candidates cut review thrash.**
`[HYPOTHESIS: Binding review to a frozen candidate tree, with one bounded correction and a burned acknowledge token, reduces review→fix→re-review loops by ≥50% vs live-worktree review on 20 real tasks, with no drop in defect catch rate.]`
*Kill criterion:* <25% loop reduction, or catch rate drops >5% → keep live review and take only the "one bounded correction" rule.
*Spike:* wrap the existing Phase 3 gate in a freeze step; run 20 tasks both ways.

**H-C — The compiled RolePack holds fidelity.**
`[HYPOTHESIS: One RolePack source compiled to omp `agents/*.md`, base-pi package, and `.opencode/agents/` scores within 5% of the omp-native pack on role-fidelity (tool-surface adherence, structured-yield validity, cross-role leakage) across a fixed 6-role benchmark.]`
*Kill criterion:* compiled targets trail omp-native by >15% → pick omp as sole substrate and drop the multi-harness ambition for v1.
*Spike:* author 6 roles once, emit three targets, score with a scripted 6-role benchmark.

## 5. Direct answers to the ten questions

### Q1 — Best memory system on the market?
**No product. The best *pattern* is Claude Code's write discipline + Graphiti's supersession semantics + Codex's consolidation/forgetting, composed over our own ledger.**
Claude Code is #1 for one reason: its write path *"skips anything it can derive from the codebase"* — exactly the failure SWE-ContextBench shows destroys value (free retrieval: +27% cost, zero gain; free summaries: **worse than nothing**). Graphiti is right about *semantics* (supersession, not deletion). Supermemory is the best *measured* off-the-shelf engine. **Mem0 — the most popular — is the trap**: ADD-only by design since April 2026, and worst of four on coding tasks.

We already ship the right ladder. What the market adds is three missing pieces: (1) an explicit **code-derivability deny-list** on the write path, (2) **validity windows keyed to the plan-ledger hash chain** (stronger than `isLatest` flags), (3) **≤250-token anchored summaries** as the high-value artifact shape. Do **not** adopt a memory product as source of truth — a second history with no shared identity is the recipe for stale-fact injection. And note: *no framework market-wide has a production-grade deletion path* — which is precisely why memory must be a **rebuildable projection**, not a store.

### Q2 — Docker stack or desktop app?
**Neither alone. Hybrid: native control plane, optional containerized workers.**
Docker-only fails the two hardest constraints (macOS Metal GPU cannot enter the Docker VM at all; Claude Code's OAuth lives in the macOS Keychain) and taxes the git-worktree engine that is our core (bind mounts ~3× slower than native on macOS). It also drags in the Docker Desktop license wall. Desktop-only gives up containment of agent-written code. The shape is Goose's (native, Rust, ACP) with OpenHands-style sandboxing applied to *workers only*. Docker becomes a capability you opt into, never a prerequisite for install.

### Q3 — Agents: BYO volume, or agent-manager installs?
**Detect-then-install hybrid, with BYO as the default path.**
(1) Probe `which claude codex opencode pi agy` and known config dirs; if present, register `source: host`. Zero install friction, zero OAuth rework. (2) Install only what's missing into `~/.studio/harness/bin/<name>/<version>/` — a **host-side** versioned directory, never an image layer, so weekly harness updates don't require an engine release. (3) **Never prebake harness CLIs into an image** — highest ToS/license risk (you would be shipping Claude Code/Codex binaries), worst update skew, and OAuth breaks. (4) Per-lane config dirs created by the manager (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `OPENCODE_CONFIG_DIR`, `~/.gemini/antigravity-cli`) so parallel coders don't thrash one shared refresh token. (5) The existing SecretBroker holds refresh material and mints short-TTL access tokens just-in-time.

### Q4 — Persistence across image updates?
**One named volume per class, host-identical bind paths, versioned migrations, and the engine owning all git.**

| Volume | Contents | Type | Survives update |
|---|---|---|---|
| `studio-state` | `studio.db` (+WAL), `schema_migrations` via `PRAGMA user_version` | named | yes |
| `studio-evidence` | content-addressed sha256 blobs | named | yes |
| `studio-logs` | engine/scheduler/adapter JSONL, rotated | named | yes |
| `studio-harness` | per-harness config + auth, **per-lane subdir** | named | yes |
| `studio-toolchains` | node/python/uv/rustup caches, models | named (ro into workers) | yes |
| repos + `.worktrees/` | user-owned | **bind, host-identical path** | yes — never in an image |

Rules: (a) worker images version independently of the engine — never put a harness CLI version in the engine's version string; (b) `VACUUM INTO` backup before every migration, and a `/state/.layout-version` stamp the engine refuses to boot against if unknown; (c) never one mega-volume — that is exactly the 100GB/8h never-delete failure mode; (d) worktrees live on the host and only their *contents* are bind-mounted, with engine-owned `git worktree add/lock/prune` — this is what makes image swaps safe mid-task `[VERIFIED: microsoft/TypeAgent#2365]`; (e) `studio export` → tarball of db + evidence + config-without-secrets, secrets only under `--include-secrets` into an age envelope.

### Q5 — Forgo bring-your-own-agent and hand-build configs?
**Yes — that is the RolePack play. But split by auth kind, because subscriptions and API keys are not the same problem.**
Hand-built agents work beautifully for **API-key and free-tier** paths: OpenCode Zen/Go are ordinary API keys despite the branding `[VERIFIED: opencode.ai/docs/providers]`; pi's provider table already lists them alongside ~30 others. One RolePack, many model slots.

They **cannot** absorb OAuth subscriptions. Anthropic explicitly prohibits third-party harness use of Claude Pro/Max (OpenCode removed bundled plugins over it), and pi warns third-party harness use draws per-token extra usage rather than plan limits. So: **subscriptions ride harness delegation** (`auth_kind: cli_delegated`, ACP adapter owns the OAuth dance), **API keys ride our Model Fabric**. Both feed the same role slots. This is not a compromise — it is the only ToS-clean shape, and our session bridge is already the delegation mechanism.

### Q6 — How do we handle LLM APIs?
**Hybrid: in-process Model Fabric + credential store + role slots. External gateways are provider profiles, never a dependency.**
- **Model Fabric** (Rust, in `studio-core`): pi-ai-shaped unified client across `anthropic-messages` / `openai-completions` / `openai-responses` dialects, per-model `cost{input,output,cacheRead,cacheWrite}`, retries/circuit breaker, session-sticky cache affinity.
- **Credential store**: `auth_kind: api_key | oauth | local | cli_delegated | cloud_iam`, secrets in keyring, resolution supporting `$ENV` and `!cmd` (pi's pattern). **Discovery over configuration** — detect what's already logged in.
- **Role slots** (`role.coder`, `role.reviewer`, …) resolve through ordered **pools**; the DAG names slots, never providers. This is the "don't make me a router admin" surface.
- **Gateways as profiles**: LiteLLM / OpenRouter / **OmniRoute** / BiFrost / Requesty plug in as `base_url` + key + namespace import. OmniRoute is the strongest integration candidate — it is real, it already runs in this workspace, and Context Relay is the only public design for OAuth account rotation.
- **Assignment: pinned tiers by default** (ship three onboarding profiles — "Max-first", "API-cheap", "Local-only" — as editable rows). Per-role override for power users. Auto-routing opt-in per slot, **forbidden on `coder.primary` and `reviewer`** (review independence). Budget arms on `input+output+cache_write`, **excluding `cache_read`** (already correct in the roadmap).
- **The UI must not lie.** Four states only: pick source → connect with a **live ping proof** (never "Connected" from a saved string) → assign roles showing *which account gets billed* → live status with a 24h staleness rule. Import harness configs read-only; if we push config outward, it is an explicit "export to harness" action with a diff preview.

### Q7 — Dedicated pi profiles? pi or opencode?
**Yes — you would not be early. Build a multi-harness RolePack with oh-my-pi as the primary runtime target.**
The market is unambiguous: gsd-core ships 36 specialists + 72 skills across 9+ harnesses including pi; `wshobson/agents` has 40k stars; 5 of the top ~45 pi.dev packages are role systems; omp has typed `AgentDefinition` with schema-yielded `output`, `spawns`, `autoloadSkills`, and role-aliased models.

**Substrate verdict:** oh-my-pi wins capability and real isolation (`omp --profile`); base pi wins distribution (Pi Package format, pi.dev catalog); OpenCode wins mindshare (210k★) and JSON-Schema config. **And omp already ingests OpenCode config at priority 55** — so an OpenCode-shaped pack is readable by omp today, but not the reverse. That asymmetry is the decision.

Recommendation: author once against **omp's `AgentDefinition`** (not base pi's `ExtensionAPI` — base pi may absorb subagents/MCP and collapse the third-party market), emit an omp-native drop + base-pi `package.json#pi` shim + `.opencode/agents/` mirror, and run H-C before committing to multi-harness for v1. Our existing `RolePack` struct grows: system prompt, skill lockfile (already), MCP slice, **model slot bindings**, harness profile, and a registration-parity test (already).

### Q9 — Skills/MCP per profile?
**Lockfile-pinned asset manifests, not ad-hoc installs.** Parallel worktrees must see an identical tool surface or you get "works in my worktree" drift. kasetto's model is the right one: four asset kinds (skills, commands, MCPs, instructions) from one source, transformed per agent, content-hashed into a lock, `--locked` in CI. Combine with our existing compile-checked tool manifests (registration parity already catches phantom tools — the opencode-swarm v6.48.0 class of bug) and keep the **per-role schema token cost scoreboard** from Phase 2. Assets resolve secrets at bind time via the SecretBroker; nothing secret is ever written into the lock or into an agent settings file.

### Q10 — Coding standards?
**Defense in depth, process-level, SARIF-shaped. And "fallaw" is Flawfinder — skip it (C/C++ only).**

| Layer | What runs | Budget |
|---|---|---|
| 0 — agent loop | format-on-write, ast-grep invariants, SARIF findings as fix-tasks | <2s, <500 tok |
| 1 — session (Stop) | tdd-gate, scope-guard, secret-scan, severity budget on the diff | <10s |
| 2 — pre-commit (**`prek`**, not lefthook) | `rustfmt --check`, `clippy -D warnings` (changed crates), `ruff`/`oxlint`, gitleaks, **config-integrity** | <15s |
| 3 — pre-push | typecheck affected, unit tests affected, `cargo-audit`/`osv-scanner` on lockfile change, **marker-file freshness** | <90s |
| 4 — merge queue / CI | full matrix, Semgrep (custom rules), CodeQL on critical paths, trivy SBOM+CVE, `cargo-deny` licenses, **SARIF aggregate gating NEW findings only** | fail-closed |
| 5 — continuous | nightly audits, weekly CodeQL, auto baseline-ratchet PRs, rule-acceptance analytics | scheduled |

**LSPs:** use them as navigation aids behind a broker; do **not** make them the gate. OpenCode's own docs say CLI diagnostics are often better. Priority order if we do wire LSP: rust-analyzer → tsserver → basedpyright → gopls. jdtls is not worth embedding.

**Anti-circumvention (this is the part that actually matters):**
1. PreToolUse **command** hooks (not prompt hooks, not `permissions.deny`) blocking `--no-verify`/`-n`, `core.hooksPath` overrides, `HUSKY=0`/`LEFTHOOK=0`/`SKIP=*`, `git stash`+commit combos, quiet flags, and writes to gate configs (`.claude/settings.json`, `lefthook.yml`, `.pre-commit-config.yaml`, `biome.json`, `clippy.toml`, `tsconfig.json`, `Cargo.toml [lints]`).
2. **Block the MCP bypass** — deny `push_files` / `create_or_update_file` / `merge_pull_request` write-throughs that skip local hooks. `block-no-verify` already implements this list.
3. **Marker-file freshness**: pre-commit writes a tree-hash marker; pre-push rejects if stale. Survives `--no-verify` on commit.
4. **Config-integrity CI**: any diff to gate configs requires CODEOWNERS approval. Agents cannot self-approve.
5. **Suppressions never live in source.** All `#[allow]` / `eslint-disable` / `# type: ignore` route to a SARIF suppression file with a required justification, owned by CODEOWNERS. Flawfinder's RealNetworks CVEs are the cautionary tale.
6. **CI runs with ignores disabled** (`clippy --force-warn`, pinned ruff config) so the answer never depends on what the agent wrote into the file.
7. **Agent credentials are read-only for CI** — push lands as PR; merge requires Layer 4.
8. Log every Bash command. Git doesn't record `--no-verify`; our hooks must.

Severity policy: **block new error-level findings only.** A "zero findings" gate on a legacy repo is how you teach an agent to mass-generate `// ignore` comments.

## 6. Shape of the next phase

Three workstreams, ordered by dependency:

1. **Fabric substrate (blocking):** real auth-material subsystem (keychain bridge, token file materialization, refresh lifecycle — currently a stub with only `profile_dir` + `SecretBroker` mint/redeem), Model Fabric, connection/pool/role-slot store. Without this, RolePacks have nothing to bind to and subscriptions don't work at all.

Explicitly **out of scope**, consistent with the roadmap boundary: marketplace, cloud hosting, mobile companion, voice.

## 7. Rejected convergences (explicitly not recommended)

- **"Adopt Mem0 / Letta / Supermemory as our memory."** A second history with no shared identity to the ledger is the stale-fact injection recipe; Mem0 is ADD-only by construction and worst-in-class on coding tasks.
- **"Ship a Docker Compose stack as the product."** Breaks macOS OAuth and Metal GPU, taxes git at 3×, and drags in the Docker Desktop license wall.
- **"Prebake harness CLIs into images."** Highest ToS risk, worst update skew, OAuth dies.
- **"Auto-route models to save cost."** Tool-dialect churn, cache-cold hops, context mismatch, reviewer correlation. Coding DAGs fail for reasons that look like agent flakiness.
- **"Build our own LSP layer as the gate."** OpenCode's own docs recommend against it; CI parity is what matters.
- **"Use lefthook."** Broken in linked worktrees; OOM risk under agent fan-out.
- **"Author a large catalog of RolePacks."** That is content, and `wshobson/agents` has 40k stars of it. Prove the runtime with one pack.
- **"Require LiteLLM/OmniRoute."** Punishes local-first; turns "connect a model" into "deploy a gateway."
- **"Zero-findings quality gate."** Teaches the agent to suppress. Budget on *new* errors.
- **"Prompt rules to prevent gate bypass."** Field evidence: 6 consecutive bypassed commits despite explicit CLAUDE.md rules. Process-level or nothing.
